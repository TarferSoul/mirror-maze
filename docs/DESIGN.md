# 技术设计

## 模块边界

`levels.js` 提供纯地图数据；`engine.js` 负责合法性判断、状态转换与求解；`app.js` 负责把用户输入转换成动作并渲染新状态；`storage.js` 负责验证和保存本机成绩。规则层不读 DOM、不访问存储、不播放音效，因此能够独立测试。

## 状态建模

```js
{
  (x,
    y, // 玩家所在格
    world, // 0：现实；1：镜像
    keys, // 已收集钥匙的位掩码
    switches, // 已激活机关的位掩码，A=1，B=2
    moves, // 有效移动次数
    shifts, // 有效切换次数
    won); // 是否通关
}
```

两张地图共享宽高。每个钥匙按“世界、列、行”分配唯一位；全部钥匙的掩码为 `(1 << keyCount) - 1`。世界切换保持坐标不变，但也会触发目标格上的收集、机关或出口事件。

`transition(level, state, action)` 不修改旧对象，而是返回 `{ state, changed, event/reason }`。合法动作产生新状态，非法动作返回原状态。旧对象可安全存入撤销栈，撤销时直接恢复。提示次数是本局的独立统计，不随撤销减少。

## BFS 最短路径

求解器的去重键为 `(x, y, world, keys, switches)`。步数不影响后续可执行动作，因此不进入去重键。每个状态最多有 5 条边：上、右、下、左和切换。每条边的代价都是 1，广度优先搜索首次遇到终点时即可得到最短动作序列。

搜索队列保存父节点索引与当前动作，找到终点后沿父节点回溯。没有为每个搜索节点复制完整路线，队列采用递增下标，避免重复 `shift()` 带来的数组搬移。

若地图包含 `W × H` 个格、`K` 把钥匙和 `P` 个机关，粗略状态上界为：

```text
S ≤ 2 × W × H × 2^K × 2^P
时间复杂度 O(S)，空间复杂度 O(S)
```

本项目最多 11 × 9 格、2 把钥匙和 2 个机关，且大量状态不可达，适合同步求解。若扩展到大型地图或大量机关，应增加搜索预算或迁移到 Web Worker。

## 无死局验证

仅验证起点能到出口，无法保证中途不会出现死局。测试进一步穷举从起点出发的所有可达状态，记录反向边；随后以全部胜利状态为起点执行反向遍历。如果反向可达集合与正向可达集合完全一致，则每个可达状态都存在后续通关路径。

游戏不允许关闭已激活的机关，这使谜题保持可预测，也减少误操作产生的死局。无死局测试仍直接验证实际状态图，不依赖这一设计假设。

## 存档与边界

存档键为 `mirror-maze:v1`。加载时校验版本、计数类型与范围，只接受本项目的关卡 ID，并根据连续通关记录限制可选择关卡。写入失败不会中断游戏，界面会提示本次进度无法保存。

存档只在当前浏览器、当前来源内有效，不包含账号或网络请求，不提供防作弊能力。它记录最佳通关成绩与最后选择的关卡，不保存进行中的局面。

## 新增关卡

在 `src/levels.js` 的数组中增加对象。地图字符串长度必须一致，两张地图尺寸必须相同，恰好包含一个出口，出生点必须为普通地面。

| 符号      | 含义       |
| --------- | ---------- |
| `#`       | 墙壁       |
| `.`       | 普通地面   |
| `k`       | 钥匙       |
| `a` / `b` | 机关 A / B |
| `A` / `B` | 门 A / B   |
| `E`       | 出口       |

坐标从左上角的 `(0, 0)` 开始。新增地图后，更新测试中的已知最短步数与课程说明，并运行全部测试。`solve(level)` 返回 `null` 表示不可解。
